# Deploying to Render

Everything here is free tier. Budget: zero rupees.

Read the **Free-tier traps** section before your demo, not after.

---

## What you will end up with

| Resource | Render name | URL |
|---|---|---|
| PostgreSQL | `aigym-db` | internal only |
| FastAPI backend | `aigym-api` | `https://aigym-api.onrender.com` |
| React frontend | `aigym-web` | `https://aigym-web.onrender.com` |

Plus two optional external services, both free:

| Service | Provider | Needed for |
|---|---|---|
| MongoDB | Atlas M0 | raw signal archive, session replay, per-rep metrics on real data |
| MQTT broker | HiveMQ Cloud or `broker.emqx.io` | the real ESP32 |

The app runs without both. You lose the archive and the hardware path, not the
demo.

## Step 1 — Push to GitHub

```bash
cd C:\Users\kesha\desktop\ai-gym-assistant
git add .
git commit -m "AI Gym & Fitness Assistant"
```

Create an empty repository on GitHub (no README, no .gitignore — you have
both), then:

```bash
git remote add origin https://github.com/<your-username>/ai-gym-assistant.git
git branch -M main
git push -u origin main
```

**Check `.env` is not in the push.** `git status` must never list it. If you
ever commit a secret, rotating it is the only fix — deleting the file from the
next commit does not remove it from history.

---

## Step 2 — Create everything from the Blueprint

1. Go to <https://dashboard.render.com> and sign in with GitHub.
2. **New** → **Blueprint**.
3. Pick your `ai-gym-assistant` repository. Render finds `render.yaml`.
4. Give the blueprint a name and click **Apply**.

Render now creates the database, the API and the static site. The first build
takes **8–12 minutes** — `scikit-learn` and `xgboost` are large wheels. Later
deploys are faster.

`JWT_SECRET` is generated by Render automatically. `DATABASE_URL` is wired from
the database automatically. You do not type either.

---

## Step 3 — Point the two services at each other

This is the step everyone forgets, and it produces a blank page with a CORS
error in the console.

1. Open the **aigym-api** service → copy its URL
   (e.g. `https://aigym-api.onrender.com`).
2. Open **aigym-web** → **Environment** → set:
   ```
   VITE_API_BASE = https://aigym-api.onrender.com
   ```
   Then **Manual Deploy → Deploy latest commit**. Vite inlines this value at
   **build** time, so a restart is not enough — it must rebuild.
3. Copy the **aigym-web** URL (e.g. `https://aigym-web.onrender.com`).
4. Open **aigym-api** → **Environment** → set:
   ```
   CORS_ORIGINS = https://aigym-web.onrender.com
   ```
   Save; the API restarts on its own.

**Verify:** open `https://aigym-api.onrender.com/health`. You want
`"status":"ok"` and `"dialect":"postgresql"`. If the dialect says `sqlite`,
`DATABASE_URL` did not reach the service.

Then open the frontend, register an account, and record a set.

---

## Step 4 (optional) — MongoDB Atlas

Without this, `/health` reports `mongo: disabled` and you lose the angle-trace
chart, session replay, and per-rep metrics on real data.

1. Sign up at <https://www.mongodb.com/cloud/atlas/register>.
2. Create a **free M0** cluster (pick a region near you).
3. **Database Access** → add a user with a password. Use a generated password
   with no `@ : / ?` in it — those break connection-string parsing.
4. **Network Access** → **Allow access from anywhere** (`0.0.0.0/0`). Render's
   free tier has no fixed outbound IP, so an allow-list cannot work.
5. **Connect** → **Drivers** → copy the `mongodb+srv://...` string and put your
   password in it.
6. In Render, on **aigym-api**, set `MONGO_URL` to that string.

**Verify:** `/health` now shows `"mongo":"connected (aigym)"`.

---

## Step 5 (optional) — MQTT for the real ESP32

Quickest path, no account:

```
MQTT_HOST  = broker.emqx.io
MQTT_PORT  = 1883
MQTT_TOPIC = gym/+/imu
```

This is a **public** broker: anyone can read your topic and publish to it. Fine
for a college demo, not for anything real. Use a device id nobody will guess,
and say this in the report's limitations section.

For a private broker, HiveMQ Cloud's free tier gives you 100 connections:
set `MQTT_HOST`, `MQTT_USERNAME`, `MQTT_PASSWORD`, `MQTT_PORT=8883`, and
`MQTT_TLS=1`.

**Verify:** `/health` shows `"mqtt":"connected (...)"`, and after powering the
ESP32, `/api/imu/status` shows `samples_seen` climbing.

---

## Step 6 (optional) — the LLM coach

Set `ANTHROPIC_API_KEY` on **aigym-api**. Leave it blank and the deterministic
rule-based coach answers instead — it still quotes the user's real numbers, and
it never fails because an external API was down during your viva.

## Free-tier traps

**Services sleep after 15 minutes idle.** The first request then takes ~50
seconds while the container restarts. The frontend shows a "waking up" message
rather than a bare error, but **open the site two minutes before you present.**

**Free PostgreSQL is deleted 30 days after creation.** Not paused — deleted.
Put a reminder in your calendar now. Before it expires, export anything the
report depends on:

```bash
# From the Render dashboard, copy the External Database URL, then:
pg_dump "<external-database-url>" > backup.sql
```

Better: run the evaluation and export your labelled sessions to
`backend/data/sessions/*.json` and commit those. They are the actual evidence;
the database is just where they were staged.

**The build can run out of memory.** If the backend build or first request is
OOM-killed, remove `xgboost` from `backend/requirements.txt`. `habit_model.py`
detects the missing wheel and falls back to scikit-learn's
`HistGradientBoostingClassifier` with no other change.

**Camera needs HTTPS.** Browsers only allow `getUserMedia` on `https://` or
`http://localhost`. Render gives you HTTPS automatically, so this only bites if
you try to demo from a LAN IP like `http://192.168.1.5:5173`.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Frontend loads, every request fails, console says CORS | `CORS_ORIGINS` not set on the API | Step 3.4 |
| Requests go to `localhost:8000` in production | `VITE_API_BASE` unset or not rebuilt | Step 3.2, then **redeploy** |
| `/health` shows `"dialect":"sqlite"` in production | `DATABASE_URL` missing | Check the `fromDatabase` block in `render.yaml` |
| `ModuleNotFoundError: app` | `rootDir` not set to `backend` | Check `render.yaml` |
| `bash: ./start.sh: Permission denied` | git dropped the executable bit | Already handled: the start command is `bash start.sh` |
| WebSocket fails, page is `https` | Mixed content — `ws://` from an `https://` page | `wsUrl()` upgrades to `wss://` automatically; check `VITE_API_BASE` starts with `https://` |
| `alembic upgrade head` fails on deploy | Empty or half-migrated database | `start.sh` falls back to `create_all`; check the deploy log |
| Blank white page, console: `Failed to fetch dynamically imported module` | Stale cached build | Hard refresh (Ctrl+Shift+R) |
| Pose model never loads | Build-time download failed | The app falls back to the Google CDN; check the browser network tab |

## Local production check before you deploy

Catches most deployment problems in 30 seconds, on your own machine:

```bash
cd frontend
npm run build
npm run preview        # serves the real production bundle on :4173
```

If that works against a locally running backend, the Render deploy is mostly a
configuration exercise.
